# 第 1 章 · 项目概览与整体架构

## 1.1 Mario 是什么

Mario 是一个用纯 C 编写的**字节码虚拟机（bytecode VM）**。它的设计目标可以概括为三个词：

- **小**：核心引擎基本就是 `mario.c` + `mario.h` 一对文件，代码量数千行。
- **无依赖**：不依赖任何第三方库，甚至把 `malloc`/`free`/`print` 都抽象成了「平台函数指针」，方便移植到嵌入式系统。
- **语言可插拔**：VM 本身不认识 JavaScript。它只认识**字节码**。语言前端（词法 + 编译器）是独立模块，通过一个函数指针挂进 VM。

本仓库 `mario_vm` = **Mario 内核** + **JavaScript 语言前端** + **内建类库** + **命令行工具**。

## 1.2 分层结构

从上到下，整个系统分成四层：

```
┌─────────────────────────────────────────────┐
│  应用层：bin/mario/mario.c (命令行 main)       │  运行 .js / .mbc，dump 字节码
├─────────────────────────────────────────────┤
│  语言层：lang/js/                              │  JS 词法、编译器、内建 native 类
│    - compiler.c      (JS → 字节码)             │
│    - native/...      (Console/String/Array...) │
├─────────────────────────────────────────────┤
│  内核层：mario/mario.c                         │  字节码结构、对象模型、GC、执行引擎
│    - bytecode_t / var_t / node_t / vm_t        │
│    - vm_run() 主循环                           │
├─────────────────────────────────────────────┤
│  平台层：_platform_malloc/free/out             │  由宿主环境提供的三个函数指针
└─────────────────────────────────────────────┘
```

**平台层**是移植的关键。看 [`bin/mario/mario.c`](../../../bin/mario/mario.c) 里的 `platform_init()`：

```c
void platform_init(void) {
    _platform_malloc = malloc;   // 也可以是嵌入式自己的内存分配器
    _platform_free   = free;
    _platform_out    = out;      // 输出字符串，通常写到串口/标准输出
}
```

只要在你的平台上实现这三个函数，Mario 内核就能跑起来。

## 1.3 一条脚本的生命周期

以运行 `test/js/class.js` 为例，数据是这样流动的：

```
1. main() 读取 .js 文件内容成字符串 s
2. vm_new(js_compile, ...) 创建 VM，把 JS 编译器函数指针挂上
3. vm_init(vm, reg_all_natives, ...) 注册所有内建类（Console/String/...）
4. vm_load(vm, s)
     └─► 调用 js_compile(bc, s)
           ├─ 词法分析：字符流 → token 流
           └─ 语法分析：token 流 → 字节码，写入 bc.code_buf，字符串写入 bc.mstr_table
5. vm_run(vm)
     └─► 从 pc=0 开始，逐条取出 32 位指令，分发给对应的 handler 执行
           └─ handler 操作 var_t 对象、压栈/弹栈、跳转、调用函数
6. vm_close(vm) 释放资源
```

其中第 4 步（编译）和第 5 步（执行）是完全分离的两个阶段。这意味着你可以**只编译不运行**（生成 `.mbc` 文件，见第 10 章），也可以**跳过编译直接加载**已经编译好的字节码。

## 1.4 核心数据结构一览

这些结构体都定义在 [`mario/mario.h`](../../../mario/mario.h)，后续章节会详细展开，这里先建立整体印象：

| 结构 | 一句话说明 | 详见 |
| --- | --- | --- |
| `bytecode_t` | 编译产物：一个指令数组 `code_buf` + 一张字符串表 `mstr_table` | 第 3 章 |
| `vm_t` | 虚拟机实例：持有字节码、操作数栈、作用域栈、GC 状态、内建变量 | 第 6 章 |
| `var_t` | 脚本世界里的「值」：整数/浮点/字符串/对象/布尔/null/undefined，统一表示 | 第 7 章 |
| `node_t` | 对象的「成员」：一个名字 + 一个 `var_t`，是属性/数组元素的载体 | 第 7 章 |
| `func_t` | 函数：要么是脚本函数（记录字节码入口 `pc`），要么是原生函数（记录 C 函数指针 `native`） | 第 7、9 章 |
| `scope_t` | 作用域：函数/块/循环/try 各自形成一层作用域，串成作用域栈 | 第 6、7 章 |
| `lex_t` | 词法分析器状态 | 第 4 章 |

## 1.5 基于栈的执行模型

Mario 是一台**基于栈（stack-based）**的虚拟机，而不是基于寄存器的。所有运算都围绕一个操作数栈进行：

- 计算 `1 + 2` 时：先把 `1` 压栈，再把 `2` 压栈，然后 `PLUS` 指令弹出两个值、相加、把结果压回栈。
- 这种模型指令少、编译器实现简单，非常适合小型 VM。

VM 里其实有两个「栈」，不要混淆：

1. **操作数栈** `vm->stack[]`：存放计算中间值（`var_t*` 或 `node_t*`）。
2. **作用域栈** `vm->scope_stack[]`：存放嵌套的作用域（函数调用、代码块、循环、try）。

第 6 章会详细讲这两个栈如何配合。

## 1.6 为什么值得学习这个项目

- 它是**理解「一门语言如何被实现」的极佳教材**：词法 → 语法 → 字节码 → 执行，全链路都在几千行 C 代码里，没有庞杂的工程噪音。
- 它展示了**如何在资源受限环境做内存管理**：引用计数 + 标记清除的混合 GC，外加变量对象缓冲池复用。
- 它展示了**如何做可扩展设计**：语言前端可替换、原生类可注册、平台函数可注入。
